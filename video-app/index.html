교사용 준비 안내 새 영상·실제 비교 자료·공유 방식 사전 준비

사용자가 Drive Vision의 정상 동작을 확인했습니다. 수업 전에는 사용할 Workflow와 모델 버전, 새 영상의 성공·실패 장면, 초당 2회·5회 분석 비교 자료를 준비합니다. 현재 실습 ZIP은 로컬 앱이며 외부 배포 주소는 별도 준비가 필요합니다.

수업은 검증·발표를 중심으로 진행합니다. 공유 주소가 없으면 별도 PC 실행으로 대체하고 활동지에 구분합니다. 설치·계정 생성·모델 재학습은 수업 전에 준비하거나 후속 과제로 남깁니다.

  • L4-02 · 같은 장면 조건 비교

50분 진행안 · 캡처 목록 · 공유 체험 준비

01 / CRITERIA5분

무엇을 확인하면 잘 만든 앱일까요?

내 영상에서 잘 된 AI,
처음 보는 도로에서도 잘 될까요?

  • 새 영상에서 성공과 실패를 근거로 설명합니다.
  • 같은 장면의 표시 조건을 비교합니다.
  • 다른 환경에서 확인하고 개선 계획을 발표합니다.

결과물: 성공·실패 캡처 2장 + 조건 비교표 + 개선 계획 한 문장

  • 객체실제 대상과 종류·박스 위치가 맞는가?
  • 도로 영역line이 차선 사이의 주행 가능 도로를 따라가는가?
  • 신호 안내감지된 색과 안내가 일치하고, 미분석 때 이전 안내가 사라지는가?

한두 장면의 관찰로 모델 전체 정확도를 계산하지 않습니다. 퍼센트는 개별 예측의 신뢰도입니다.

02 / TEST15분

새로운 블랙박스 영상으로 검증하기

  1. 학습에 쓰지 않은 촬영 영상부터 선택합니다.

    같은 source.mp4의 인접 장면보다 촬영 시각·도로가 다른 영상이 좋습니다.

  2. 객체·도로·신호를 볼 시각을 정합니다.

    대상이 실제로 있는지 사람이 원본을 먼저 확인합니다.

  3. 영상 출처와 사용 조건을 기록합니다.

    얼굴·번호판·계정 정보가 보이는 캡처의 공유 범위를 확인합니다.

새 영상이 없으면 기존 영상으로 앱 동작만 점검하고, 새 환경에 대한 성능 검증과 구분해 기록합니다.

  1. Drive Vision에서 준비한 영상을 선택합니다.

    기본: 신뢰도 50%, 초당 2회, 묶음 8장, 동기화 재생 켜기.

  2. 분석을 시작하고 완료된 구간을 확인합니다.

    MODEL RESULT를 확인합니다. 분석 대기는 검출 실패와 다릅니다.

  3. 좋은 장면과 실패 장면에서 일시정지합니다.

    장면의 시각·대상·보이는 현상을 기록합니다. 실패를 찾지 못했다면 관찰 범위를 적습니다.

앱 실행·Workflow 연결 안내 · 현재 실습 앱 ZIP

관찰기록할 근거
놓침대상이 있는데 해당 예측이 없음
오탐·잘못된 종류없는 대상에 박스가 생기거나 색·종류가 다름
경계 어긋남박스가 벗어나거나 도로 마스크가 보도까지 침범함
판단 보류원본도 흐리거나 분석이 아직 완료되지 않음

“못 찾는다” 대신 “영상 ○초에서 사람 1명을 놓쳤다”처럼 적습니다.

신호 인식과
실제 주행 판단은 다릅니다.

  • 초록 신호가 다른 차로에 적용될 수 있습니다.
  • 보행자·정지선·주변 차량의 상황도 필요합니다.
  • 현재 앱은 신호 색에 따른 학습용 안내를 표시합니다.
현재 앱의 안내 규칙 확인

빨강 → 노랑 → 색 미확인 → 초록 순으로 우선합니다. 신호가 없으면 신호 확인, 현재 구간의 결과가 없으면 분석 대기입니다. 실제 운전 판단에 사용하지 않습니다.

L4-CAPTURE-01성공·실패 장면 캡처

현재 화면 저장으로 성공 01-success.png, 실패 02-error.png를 준비합니다. 같은 결과에 대응하는 재생 시각·신뢰도 기준·모델 정보를 활동지에 기록합니다. API 키는 포함하지 않습니다.

03 / COMPARE10분

한 번에 한 조건만 바꾸기

  1. 분석이 끝난 같은 시각에서 일시정지합니다.

    영상·Workflow·클래스·불투명도를 고정합니다.

  2. 최소 신뢰도만 40% → 70%로 바꿉니다.

    남은 대상·사라진 대상·놓침을 비교합니다. 이 표시 변경 자체는 API를 다시 호출하지 않습니다.

  3. 어떤 조건이 이 장면에 적절한지 설명합니다.

    박스가 적다고 더 정확한 것은 아닙니다.

화면 기준은 이미 받은 예측만 거릅니다. Workflow에서 먼저 제외한 예측을 복원하지는 못합니다.

3분 영상 기준초당 2회초당 5회
분석 이미지360장900장
분석 간격0.5초0.2초
8장 묶음 요청약 45회약 113회

표는 순서대로 전체를 처리할 때의 계산 예시입니다. 실제 대기 시간은 교사가 준비한 측정 기록으로 비교합니다.

분석 빈도를 바꾸면 새 분석이 필요합니다. 영상의 원본 재생 fps는 유지되며, 분석이 늦으면 동기화 모드에서 대기합니다.

지금 바꾸는 화면

  • 최소 신뢰도·표시할 클래스
  • 도로 영역 불투명도
  • 이미 받은 결과의 보이는 방식

다음 버전의 모델

  • 놓친 상황의 학습 자료 추가
  • 잘못 붙인 정답·경계 수정
  • 새 버전 학습 후 남겨 둔 영상으로 확인

분석 빈도를 높이면 더 자주 갱신합니다. 모델이 대상을 더 잘 배웠다는 뜻은 아닙니다.

  • 같은 재생 시각의 40%·70% 캡처를 저장합니다.
  • 분석 기록 JSON과 Workflow/모델 버전을 함께 기록합니다.
  • 비교표에는 관찰 사실과 원인 추정을 나누어 적습니다.

“노란 신호를 놓쳤다”는 관찰, “작은 신호 학습 자료가 부족할 것 같다”는 추정입니다.

같은 Workflow ID라도 연결된 모델이 달라질 수 있으므로 교사가 사용한 모델 버전도 기록합니다.

L4-CAPTURE-02같은 장면의 조건 비교

03-threshold-040.png와 04-threshold-070.png를 같은 재생 시각에서 저장합니다. 교사는 2회·5회 분석 비교의 실제 처리 시간과 기준 장면을 미리 준비합니다. 측정하지 않은 시간은 비워 둡니다.

04 / SHARE10분

다른 환경에서도 확인하기

  1. 강의 자료GitHub Pages

    강의 HTML·PDF·실습 ZIP을 제공합니다.

  2. 내 컴퓨터127.0.0.1:7862

    내 PC에서 실행한 Python 앱에 접속합니다.

  3. 공유 앱교사의 배포 주소

    서버에서 실행 중인 앱을 다른 기기로 사용합니다.

GitHub에 코드를 올리는 것만으로 Python 앱 서버가 실행되지는 않습니다.

근거: GitHub Pages의 정적 호스팅

  • 실행 환경Python 서버가 실행되는 환경과 필요한 패키지를 준비합니다.
  • 접속 설정서버 주소·허용 호스트·HTTPS·접근 대상을 확인합니다.
  • 모델 연결Workflow 입출력·키 권한·사용량을 확인합니다.

현재 배포 ZIP은 로컬 실행용입니다. 외부 공유에는 별도 서버 설정이 필요합니다. 학생 계정 생성·서버 구성은 50분 실습에 포함하지 않습니다.

A. 배포 주소가 준비되었을 때

  1. 교사가 제공한 주소에 접속합니다.
  2. 예제 또는 허용된 영상을 선택합니다.
  3. 화면·재생·결과 표시를 확인합니다.

B. 배포 주소가 없을 때

  1. 별도 PC에서 같은 ZIP을 실행합니다.
  2. 같은 영상·설정으로 확인합니다.
  3. 별도 PC 실행으로 기록합니다.

B는 실행 환경을 바꾸는 대체 활동입니다. 외부 배포 완료로 기록하지 않습니다.

공유 전 모델·설정·기기·브라우저를 기록합니다. 배포 접속 검사와 새 영상의 인식 성능 검사는 구분합니다.

L4-CAPTURE-03공유 또는 별도 PC 실행 화면

05-sharing-check.png에 실제 실행 화면을 저장합니다. 활동지에 A 배포 접속 / B 별도 PC 실행 중 수행한 방법, 기기·브라우저와 결과를 적습니다. 공유 URL이 준비되지 않았다면 임의 주소를 만들지 않습니다.

05 / SHOWCASE10분

성공과 실패를 함께 발표하기

성공 장면 1장

  • 어떤 대상을 잘 찾았나요?
  • 박스·도로 경계에서 근거는 무엇인가요?
  • 시각과 설정을 말할 수 있나요?

실패 장면 1장

  • 무엇을 놓치거나 잘못 표시했나요?
  • 모델·표시·연결 중 어느 문제인가요?
  • 다음에 어떤 자료로 다시 확인하나요?

원본도 판독하기 어렵다면 판단 보류와 그 이유를 설명합니다.

  1. 15초 · 시험 조건

    “우리는 ○○ 영상의 ○초 장면을 같은 모델로 확인했습니다.”

  2. 25초 · 성공과 실패

    “잘 찾은 것은 ○○이고, ○○에서는 이런 오류가 보였습니다.”

  3. 20초 · 개선 계획

    “다음에는 ○○를 바꾸고, 별도로 남겨 둔 영상으로 확인하겠습니다.”

짝 발표 후 2~3개 모둠만 전체 공유합니다. 전체 학생의 발표가 10분을 넘지 않게 합니다.

“좋았어요”에 더해 “○○ 장면을 추가하면 이 설명을 확인할 수 있어요”를 남깁니다.

  1. 1·2차시정답 만들기·학습

    일관된 라벨과 남겨 둔 평가 자료를 준비했습니다.

  2. 3차시앱으로 연결

    API 결과를 영상 위 박스·도로·신호 안내로 표현했습니다.

  3. 4차시검증·공유·개선

    새 영상의 성공과 실패를 근거로 설명했습니다.

“우리 모델의 다음 버전은
무엇을 더 배워야 할까요?”

최종 제출: 캡처 2장·조건 비교표·공유 방식 기록·개선 계획 한 문장. API 키는 제출하지 않습니다.

자료 안내 계산 표는 수업용 예시입니다. 실제 모델의 결과와 처리 시간은 학생·교사의 관찰로 기록합니다.
