## 검증 환경과 한계

- 기본 exec_command는 환경 초기화 오류로 실행되지 않았습니다. Node REPL의 파일 API와 자식 프로세스로 읽기·쓰기·Git 검사를 수행했습니다.
- Python 명령을 찾지 못해 로컬 HTTP 검사는 Node 서버로 수행했습니다.
- 브라우저 제어 도구의 인벤토리는 apps=[], browsers=[]였습니다.
- 별도 Chrome headless 렌더링은 GPU process isn't usable 오류로 실패했습니다.
- CPU 경로 재시도는 20초 안에 스크린샷을 만들지 못했습니다. 시각 검사 성공으로 표시하지 않았습니다.
- 검증 서버는 종료했고, 생성한 Chrome 검증 프로필 두 개는 작업폴더 내부 절대 경로 확인 후 정리했습니다.
- 브라우저 스크린샷과 실제 키보드 순회 증거는 없습니다.

## SOURCE VIDEO의 YouTube 재생 연결

- 사용자가 지정한 https://www.youtube.com/watch?v=ihokShSN51Y 영상을 SOURCE VIDEO에 iframe으로 삽입했습니다. 재생 버튼·전체 화면을 제공하고 YouTube에서 열기 링크를 함께 표시합니다. 자동 재생은 설정하지 않았습니다.
- 반응형 16:9 플레이어와 최소 높이 200px을 적용했습니다. 발표 모드에서는 플레이어 너비를 화면 높이에 맞춰 제한하며, 프레임 설명을 별도 조각으로 분리해 총 21개 발표 조각을 구성했습니다.
- iframe title, 지연 로딩, referrerpolicy, 전체 화면 권한을 지정했습니다. 외부 영상 재생에는 인터넷 연결이 필요합니다. 본문 정적 자산은 로컬 파일 그대로입니다.
- 구조 검사: HTML 태그 짝·중복 ID·중첩 발표 조각·깨진 내부 참조 오류 0건. 영상 ID와 원본 링크 일치, git diff --check 통과. 공통 보호 파일 4개의 해시 불변.
- 브라우저 인벤토리를 다시 확인했으나 apps=[], browsers=[]입니다. 실제 영상 재생·공개/임베드 허용 여부·발표 화면 넘침은 검증하지 못했습니다. YouTube 페이지와 oEmbed 조회도 도구에서 cache miss로 응답하여 영상 제목·상태를 확인한 것으로 처리하지 않았습니다.
- 기존 HTTP 검사 기록은 영상 삽입 전 파일의 응답 기록입니다. 이번 변경으로 영상 재생이나 외부 요청 성공을 검증한 것으로 해석하지 않습니다.
