# 1차시 교사용 진행안

## 수업 목표

50분 후 학습자는 객체 탐지와 인스턴스 분할의 차이를 설명하고, 프로젝트 기준에 맞춰 정답 영역을 표시한 뒤 수정할 부분을 찾을 수 있습니다.
최종 프로젝트는 단일 분할 모델과 Roboflow API를 사용하는 Python 웹앱 주행영상 인식 앱입니다.
차선 클래스의 의미는 사용자가 확정한 **차선 사이 주행 가능한 도로 영역**입니다.

## 시간표

| 경과 | 시간 | 진행 |
| --- | --- | --- |
| 00~10분 | 10분 | 도입: 오늘 목표 2분, 9개 클래스 관찰 4분, 모델·앱 흐름과 영상 프레임 4분 |
| 10~20분 | 10분 | 개념: 분류·탐지·분할 2분, 같은 도로의 박스·마스크 비교 3분, 단일 분할 모델과 앱 표시 3분, 확인 질문 2분 |
| 20~25분 | 5분 | 준비: 프로젝트·클래스·배정 이미지 확인 2분, 경계 기준 합의 3분 |
| 25~40분 | 15분 | 실습: 일반 객체 5분, 주행 가능 영역 7분, 저장 전 점검 3분 |
| 40~50분 | 10분 | 검수: 짝 활동 5분, 종료 질문 3분, 다음 차시 준비 2분 |

준비와 실습을 합쳐 승인된 어노테이션 활동 20분입니다. 총합은 50분입니다.

## 도입 자료의 현재 상태

기존 탐지 모델의 학습·평가 캡처와 Python 웹앱 앱의 로컬 검사는 확인했습니다. 사용자는 분할 모델 재학습을 시작했으며 새 모델의 실제 마스크·API 연결은 아직 확인 전입니다. 본문 도식은 결과 형식을 설명하는 수업용 개념도입니다.
완성 앱이 준비되면 00~10분 안에서 실물 시연을 추가할 수 있습니다. 사용자 제공 YouTube 링크는 주행영상 관찰 자료로 연결했으며, 학습된 모델·완성 앱의 시연 영상은 아닙니다.
source.mp4의 해상도·길이·프레임 수는 MP4 메타데이터에서 읽었습니다. 영상의 모든 장면을 검토한 것은 아닙니다.

## 박스·마스크 비교 설명 · 10~20분

1. **분류·탐지·분할 (2분):** 분류는 이미지의 종류, 탐지는 객체별 종류·사각형 위치, 인스턴스 세그멘테이션은 객체별 종류·영역을 찾습니다. 인스턴스는 “객체 하나하나”입니다.
2. **같은 도로 비교 (3분):** [비교 도식](../road-perception/index.html#box-vs-mask)에서 도로 박스의 모서리와 휘어진 경계를 짚습니다. 박스 안의 배경과 마스크 영역을 구분하고, car 1·2가 같은 종류의 서로 다른 자동차임을 설명합니다. 번호는 영상 추적 ID가 아닙니다. 표는 필요할 때 펼칩니다.
3. **단일 모델과 앱 표시 (3분):** 분할 모델 하나를 호출한 뒤 일반 객체는 박스, line은 도로 마스크로 표시합니다. 폴리곤으로 정답을 표시하는 도구와 학습 작업 유형을 구분합니다. Object Detection으로 학습한 결과에 색을 채워도 도로 윤곽은 생기지 않습니다.
4. **확인 질문 (2분):** “도로 누끼에 필요한 결과는?”의 정답은 영역 마스크입니다. “폴리곤만 그리면 어떤 모델이든 마스크가 나올까?”에는 프로젝트·학습 유형과 실제 출력까지 확인해야 한다고 답할 수 있는지 봅니다.

일반 객체도 분할 학습에 맞는 정답이 필요하며 기존 박스가 자동으로 실제 윤곽이 되지는 않습니다. 마스크의 정확도와 추론 속도는 모델·데이터·환경에 따라 달라지므로 “분할이 항상 정확하다/느리다”라고 단정하지 않습니다. line은 차선 페인트가 아닌 차선 사이의 주행 가능한 도로 영역입니다. 차량·장애물과 가려진 도로의 처리 기준은 프로젝트에서 합의합니다.

개념도는 추가 캡처 없이 사용합니다. 학습 완료 후 같은 시험 프레임의 탐지·분할 결과를 비교할 때는 [추가 캡처 안내](lesson-01-capture-guide.md#box-mask-comparison)를 따릅니다. 모델 비교 도식과 실제 예측을 구분합니다.

## 실습 운영

수강생은 전체 데이터셋을 처음부터 만들지 않고, 교사가 배정한 소량의 이미지에서 정답 표시와 검수를 경험합니다.
20분 안에 완성할 수 있는 이미지 수는 객체 밀도와 라벨 방식에 따라 정합니다. 우선 대표 이미지 한 장을 기준으로 실습 시간을 점검합니다.
기존 캡처 당시 프로젝트 유형은 Object Detection입니다. 도로 마스크를 출력하는 단일 분할 모델을 목표로 하므로, 기존 정답을 보존하면서 분할 학습에 사용할 수 있는지 학습 전에 확인합니다.
사용자가 제공한 car, lampg, lampr, lampy, lamp, line, motor, people, sign을 그대로 반영했습니다. sign은 표지판입니다. 초록 신호등은 lampg, 빨간 신호등은 lampr, 노란 신호등은 lampy, 신호등이지만 색을 구분하기 어려운 경우는 lamp입니다. 일반 객체의 학습용 정답 형식과 도로 영역의 포함·제외 기준도 확인합니다.

표지판은 도로 개념도와 경계 합의 항목에 포함했습니다. sign의 포함 대상과 판·지지대 경계 기준을 수업 전에 맞춥니다.
다음 준비 순서와 필수 캡처 2종은 [캡처·확인 체크리스트](lesson-01-capture-guide.md)의 다음 작업 순서를 따릅니다.

## 짝 검수 질문

1. 같은 종류의 대상에 같은 클래스를 붙였는가?
2. 작은 대상이나 가려진 대상을 프로젝트 기준대로 처리했는가?
3. 도로 영역 마스크가 의미하는 범위를 설명할 수 있는가?
4. 배경 포함·누락 영역·경계 불일치 중 한 가지를 찾아 이유를 설명할 수 있는가?
5. 저장 후 다시 열어 결과가 유지되는가?

## 종료 질문의 확인 기준

- 분류는 이미지 수준의 종류, 탐지는 종류와 박스, 인스턴스 분할은 객체별 종류와 영역을 찾는다고 설명한다.
- 차선 마스크를 차선 사이의 주행 가능한 도로 영역이라고 설명한다.
- 실제 수정한 한 곳과 기준을 연결해 설명한다.

## 교사 준비

실제 화면은 [캡처·확인 체크리스트](lesson-01-capture-guide.md)를 참고합니다.
캡처 6장을 확인하고 4장을 본문에 반영했습니다. 프로젝트 정보는 교사용 펼치기에, 자동차 박스와 도로 영역 전·후는 발표 조각에 넣었습니다.
작업 목록 2장은 계정 정보가 있어 원본만 보관합니다. 촬영 당시 201장 중 135장 라벨링·66장 미작업이며 Dataset은 0입니다.
교사용 준비 안내와 확인 메모는 발표에서 제외했습니다. 발표 조각은 총 21개이며 수업 시간은 50분을 유지합니다.
발표는 P, 이동은 방향키·PageUp/PageDown, 종료는 Esc입니다. 정답은 해당 조각의 펼치기 버튼으로 확인합니다.
2차시는 model-training/index.html, 3차시는 api-app/index.html에 작성했습니다. 4차시는 준비 중입니다. 1차시 현재 경로는 road-perception/index.html입니다.

## 주행영상 재생

SOURCE VIDEO 영역에서 사용자가 지정한 YouTube 영상을 재생합니다. 도입에서는 필요한 장면을 30~60초 관찰해 10분 배분을 유지합니다. 학습용 source.mp4 메타데이터는 파일을 직접 읽은 값이며 YouTube 영상의 재생 시간·해상도를 검증한 값은 아닙니다.
인터넷에 연결된 실제 수업 브라우저에서 재생·전체 화면·발표 모드 이동을 확인합니다. 재생이 제한되면 YouTube에서 열기 링크를 사용합니다. 플레이어를 조작한 뒤 발표 단축키를 사용하려면 영상 바깥을 클릭해 강의 화면으로 초점을 돌립니다.
