## 환경과 남은 확인

기본 셸 도구의 환경 초기화 실패로 Node REPL의 파일·프로세스 API를 사용했습니다. 번들 Python·Poppler를 사용했고 Python 패키지는 무시된 work-temp/lesson03/deps에 설치했습니다. 이 임시 설치 경로에서는 Streamlit이 개발 모드로 판단해, 서버 시작 검사에 developmentMode=false를 명시했습니다. 정상 가상환경 설치를 안내하는 사용자 앱 코드는 변경하지 않았습니다.

브라우저 인벤토리는 apps=[], browsers=[]여서 실제 화면·키보드·클립보드·모바일 검증은 수행하지 못했습니다. PDF와 예제 결과 PNG는 파일을 직접 렌더링해 시각 확인했습니다.

현재는 어노테이션을 계속합니다. 학습 완료 후 실제 모델 ID·분할 유형·Serverless 지원·line points 응답을 확인하고 실제 이미지 API 연결을 검증합니다. [캡처 안내](lesson-03-capture-guide.md)에 단계별 화면을 지정했습니다.

수행: 3차시 제작 → 산출물: 강의·앱·ZIP·PDF·안내 → 검사: 정적·자동 앱·HTTP·PDF 통과 / 실제 모델·브라우저 대기 → 다음: 실제 학습 결과 확인과 이후 영상 앱 차시. 커밋·푸시·학습·원격 프로젝트 수정·외부 배포는 수행하지 않았습니다.

## 2026-10-18 Streamlit 이미지 폭 TypeError 수정

사용자 오류: Python311 경로에서 st.image(image, width="stretch") 실행 중 문자열과 정수를 비교해 TypeError 발생. 설치된 정확한 Streamlit 버전은 확인하지 못했습니다. 공식 1.32 문서는 width를 int/None으로, 1.66 문서는 문자열 또는 int로 정의합니다.

- app.py 입력·결과 이미지와 video_ui.py 프레임 이미지의 폭을 실제 이미지 너비인 정수로 지정했습니다. 결과 표의 문자열 폭은 제거해 기본 자동 폭을 사용합니다.
- 다운로드 README에 이전 ZIP 교체와 가상환경 Python으로 설치·실행하는 방법을 추가했습니다. 설치된 PyAV 19.0.1 메타데이터에서 Python >=3.12를 확인했으므로 영상 실습의 Python 3.12 기준을 유지합니다.
- Python 3.12.14·Streamlit 1.66.0에서 기존 이미지·영상 테스트 12개 통과. 예제 표시, 결과 표, 영상 프레임·MP4 생성, 표시 변경과 세션 초기화를 검사했습니다. 실제 Roboflow API 호출은 0회입니다.
- 별도 임시 Streamlit 1.32.0의 AppTest로 width="stretch"의 동일 TypeError를 재현했고, 정수 폭으로 바꾼 최소 이미지 예제는 통과했습니다.
- 구버전에서 전체 화면 검사까지 시도한 3개 테스트는 통과하지 못했습니다. 이미지 2개는 해당 임시 환경의 PyArrow 26/NumPy 1.26 의존성 충돌, 영상 1개는 구버전 AppTest의 형식 지정 select_slider 값 직렬화 오류입니다. 구버전 전체 앱 지원을 검증한 것으로 표시하지 않으며, 배포 requirements는 1.66.0을 유지합니다.
