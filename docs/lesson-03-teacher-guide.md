# 3차시 교사용 진행안 · 50분

사용자 요청에 따라 기존 Streamlit·전체 MP4 생성 실습을 **Drive Vision 웹 대시보드**로 개편했습니다. 원본 영상을 브라우저에서 재생하고 Roboflow Workflow의 박스·line 폴리곤을 Canvas에 표시합니다. 단일 Instance Segmentation 모델과 9개 클래스는 유지합니다.

| 시간 | 진행 | 확인 |
| --- | --- | --- |
| 0~8분 | 원본 영상 + 분석 결과 구조, 예제와 실제 모델 구분 | 전체 영상 재인코딩을 하지 않음 |
| 8~18분 | ZIP·가상환경·python app.py·영상 선택 | http://127.0.0.1:7862, 원본 재생 |
| 18~28분 | Workflow 연결·배치 요청·응답 읽기 | Workspace/Workflow ID, Predictions 출력 |
| 28~42분 | 박스·도로·신뢰도·신호 안내 실습 | 임계값 비교, 빨강 우선, 미분석 표시 |
| 42~50분 | 오류 점검·기록 저장·정리 | PNG/JSON, 반복 시 API 재호출 없음 |

## 수업 전

- Python 3.11 또는 3.12, 새 실습 requirements 설치, MP4(H.264) 재생 가능한 브라우저를 준비합니다.
- 기존 어노테이션 201장과 탐지 모델 v1 평가는 확인했습니다. 사용자는 분할 모델 재학습을 시작했으며 새 모델의 마스크 출력과 Workflow 배포는 실제 확인이 필요합니다.
- 모델 하나에서 9개 클래스를 출력하는 Workflow를 준비합니다. image 입력과 predictions 출력이 기본입니다. Outputs에서 모델의 Predictions를 선택합니다.
- API 키는 캡처하지 않습니다. Workspace ID·Workflow ID는 Deploy Workflow 코드에서 복사합니다.
- 키 없이 원본 재생과 가상 도로 화면 예제를 사용할 수 있습니다.
- [실행 안내](../files/lesson-03/README.md)와 [캡처 목록](lesson-03-capture-guide.md)을 확인합니다.

## 진행 포인트

3분 영상·초당 2회 분석은 360장입니다. 기본 8장 묶음으로 전체를 순차 처리하면 약 45개 HTTP 요청이지만 이미지 사용량은 360장입니다. 한 번의 버튼 조작·HTTP 요청 수·분석 이미지 수를 구분합니다.

원본 영상은 재인코딩하지 않습니다. 먼저 끝난 구간부터 표시합니다. 분석이 느리면 기본 동기화 모드에서 잠시 기다립니다. 이를 카메라 실시간 추론이나 보장된 무지연 처리로 설명하지 않습니다. 분석 빈도와 영상 재생 fps는 다른 값입니다.

빨강은 정지, 노랑은 감속, 초록은 주행, 색 미확인·신호 없음은 확인입니다. 신호가 여러 개면 빨강을 우선합니다. 차로별 신호 연결·거리·속도를 계산하는 모델이 아니므로 실제 주행 판단용이 아닙니다.

퍼센트는 예측 신뢰도입니다. line은 도색된 선이 아닌 차선 사이의 주행 가능한 도로 영역입니다. 폴리곤 없는 line은 제외하며 오류 안내를 확인합니다.

화면 예제에서 일시정지한 같은 장면의 임계값 40/70/90%를 비교합니다. 실제 모델에서도 같은 시각으로 비교하고 PNG와 JSON을 저장합니다. 표시 조건만 바꿀 때 재분석하지 않습니다. 이 버전에는 MP4 다운로드가 없습니다.

신호 변경·반복 재생·탐색·분석 중지와 이어하기를 실제 사용자 브라우저에서 확인해야 합니다. 자동 검사와 사용자 모델의 성능 검증을 구분합니다.
